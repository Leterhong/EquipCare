## 一、部署架构

```
                 ┌────────────────────────────────────────────┐
浏览器/手机 ──►  │ frontend (nginx:1.27-alpine) :80           │
                 │  · 静态资源（原生 ES Module 单页应用）        │
                 │  · /api 反向代理 → backend:8080             │
                 └───────────────┬────────────────────────────┘
                                 │ docker network: equipcare
                 ┌───────────────▼────────────────────────────┐
                 │ backend (temurin-17-jre + app.jar) :8080   │
                 │  · Spring Boot 单体（内部网络，不直接暴露）   │
                 └──────┬──────────────────────┬──────────────┘
                        │                      │
          ┌─────────────▼────────┐   ┌─────────▼───────────┐
          │ mysql:8.4            │   │ redis:7-alpine      │
          │ volume: mysql-data   │   │ volume: redis-data  │
          │ 数据持久化            │   │ 会话/缓存            │
          └──────────────────────┘   └─────────────────────┘
          upload-data 卷：/data/uploads 设备照片与维修凭证持久化
```

## 二、部署前检查清单（在目标服务器上逐项确认）

| # | 检查项 | 命令 | 要求 |
|---|---|---|---|
| 1 | 容器环境 | `docker --version` | ≥ 24，Docker Engine 运行中 |
| 2 | Compose | `docker compose version` | v2 可用 |
| 3 | 可用端口 | `ss -tlnp \| grep -E ':80\|:443'` | 80（或 `FRONTEND_PORT`）未被占用 |
| 4 | 磁盘空间 | `df -h /var/lib/docker` | ≥ 20GB（镜像 + 数据库 + 上传文件） |
| 5 | 服务器内存 | `free -h` | ≥ 4GB（MySQL 1G + 后端 1.5G + 系统） |
| 6 | 数据库连接 | 容器内自检 | 首次部署由 init 脚本建库；已有外部数据库时改 `EQUIPCARE_DB_HOST` |
| 7 | 域名/IP 访问方式 | — | 有域名则配 DNS A 记录并建议加 HTTPS（见第八节）；否则直接用 `http://<服务器IP>` |
| 8 | 防火墙规则 | `firewall-cmd --list-all` 或 `ufw status` | 放行 80/443；**3306/6379 不对公网开放** |
| 9 | 时间同步 | `timedatectl` | NTP 已同步（巡检计划/SLA 时限依赖准确时间） |

## 三、首次部署步骤

```bash
# 1. 上传代码（或 git clone）到部署目录，例如 /opt/equipcare/equipcare-server
cd /opt/equipcare/equipcare-server

# 2. 准备环境变量（敏感信息与代码分离，.env 不入库）
cp deploy/env.example .env
vi .env    # 逐项填写强密码；生成方式：openssl rand -base64 24

# 3. 首次部署开启管理员引导
#    .env 中设置：EQUIPCARE_BOOTSTRAP_ENABLED=true
#                 EQUIPCARE_BOOTSTRAP_USERNAME=<管理员用户名>
#                 EQUIPCARE_BOOTSTRAP_PASSWORD=<强密码>

# 4. 构建并启动（首次构建需联网拉取 Maven 依赖，约 5–10 分钟）
docker compose up -d --build

# 5. 观察启动过程
docker compose logs -f backend
#    看到 "Started EquipCareApplication" 即启动成功，Ctrl+C 退出跟踪

# 6. 验证
curl -s http://127.0.0.1/actuator/health        # 经 nginx 代理到后端
# 浏览器打开 http://<服务器IP>/ 应看到登录页
```

首次部署完成后**立即**关闭引导开关：`.env` 中 `EQUIPCARE_BOOTSTRAP_ENABLED=false`，然后 `docker compose up -d` 重建 backend。

## 五、数据备份与恢复

**自动备份**（mysqldump 逻辑备份，保留 7 天）：

```bash
# 部署机 crontab：每天 02:30 备份
crontab -e
30 2 * * * /opt/equipcare/equipcare-server/deploy/backup.sh >> /opt/equipcare/backup/backup.log 2>&1
```

**手动备份**：

```bash
cd /opt/equipcare/equipcare-server
docker compose exec -T mysql mysqldump -uroot -p"$(grep MYSQL_ROOT_PASSWORD .env | cut -d= -f2)" \
  --single-transaction --routines --triggers equipcare | gzip > backup_manual_$(date +%Y%m%d).sql.gz
```

**恢复**：

```bash
gunzip < equipcare_20261031_023000.sql.gz | \
  docker compose exec -T mysql mysql -uroot -p"<root口令>" equipcare
```

**上传文件备份**：`docker run --rm -v equipcare_upload-data:/data -v /opt/backup:/backup alpine tar czf /backup/uploads_$(date +%Y%m%d).tar.gz /data`（卷名以 `docker volume ls` 实际输出为准）。

## 六、日志查看

```bash
docker compose logs -f backend     # 应用日志（含 traceId，可串联一次请求）
docker compose logs -f frontend    # nginx 访问/错误日志
docker compose logs -f mysql       # 慢查询/错误
docker compose logs --since 30m    # 最近 30 分钟全部日志
```

应用日志同时落盘到 `./logs/backend/`（Spring Boot 滚动文件），可直接 `tail -f logs/backend/*.log`。

## 七、故障排查

| 症状 | 排查 |
|---|---|
| 登录 500，日志见 Redis Connection refused | `docker compose ps` 看 redis 是否 healthy；`docker compose logs redis` |
| 后端起不来：JWT 密钥长度不足 | `.env` 的 `EQUIPCARE_JWT_SECRET` 必须 ≥32 字节 |
| 后端起不来：数据库拒绝访问 | `EQUIPCARE_APP_PASSWORD` 与 MySQL 初始化时是否一致；首次初始化后改密码需 `ALTER USER` 同步两处 |
| 页面打开但接口全 404 | nginx 代理目标是否为 `backend:8080`；`docker compose exec frontend wget -qO- http://backend:8080/actuator/health` |
| 上传文件丢失 | 确认 `upload-data` 卷存在：`docker volume ls`；切勿 `docker compose down -v`（会删卷） |
| 首页一直转圈 | `docker compose logs backend` 看是否等待 MySQL healthy；`docker compose ps` 全部应 Up/healthy |
| 手机扫码打不开 | `.env` 的 `EQUIPCARE_SCAN_BASE_URL` 未配置或不是手机可达地址 |

**紧急处理**：`docker compose restart`（服务重启，数据卷保留）；`docker compose down`（停服，卷保留）；**禁止 `docker compose down -v`**（删除数据卷）。

## 八、HTTPS（有域名/证书时）

推荐在 frontend 前再挂一层宿主机 Nginx/Caddy 或云负载均衡终结 TLS，反代到 `FRONTEND_PORT`。或修改 `deploy/nginx.conf` 增加 443 server 块并挂载证书到 frontend 容器。JWT 走 HTTP 明文有被截获风险，公网部署务必上 HTTPS。

## 九、已知部署形态差异说明

1. **本交付在 Windows 开发机完成功能与接口验证**（jar 直跑 + Playwright），容器级构建与整栈启动验证在目标服务器首次部署时进行（开发机 Docker Desktop 未运行，见 `docs/06-功能测试报告.md` 遗留事项 2）。首次 `docker compose up -d --build` 若有镜像层问题，把 `docker compose logs` 输出反馈给开发侧即可定位。
2. 若需求方提供的是**已有外部 MySQL/Redis**（而非容器新建），删除 compose 中对应 service，backend 环境变量指向外部地址即可，init 脚本改由 DBA 手工执行 `database/00-create-database.sql` → `schema.sql` → `seed.sql`。
3. 需求方服务器信息到位后，将按第二节清单逐项执行部署前检查，并回填本文档「部署记录」。
