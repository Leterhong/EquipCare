## 1. Vue 3 新前端（equipcare-web/）

- 技术栈：Vue 3.5 + Vite 6 + TypeScript + Element Plus + Pinia + vue-router（hash 模式）
- **新旧共存**：旧原生前端（static/，28 页）继续从后端服务；新前端 dev 走
  `npm run dev`（5173，/api 代理 8080），prod `npm run build` 产物由 Nginx 挂 /web/ 或独立域名
- 首批迁移：登录（双令牌 + 静默续期，localStorage 键与旧版互通）、
  布局壳（服务端菜单按权限渲染 + 未迁移项自动折叠「旧版入口」）、
  数据驾驶舱、维修工单列表
- 迁移约定见 `equipcare-web/README.md`：只迁移不改后端、迁一个注册一个（`MIGRATED` 常量）

## 2. AI 深化

### 2.1 拍照缺陷识别（多模态视觉）

- `POST /api/ai/defect-analyze`（body: fileIds ≤4 + hint）：读取 sys_file →
  上传目录磁盘文件 → base64 data URL → 视觉模型（`EQUIPCARE_AI_VISION_MODEL`，
  未配回退主模型）→ 结构化 Markdown 判定（是否缺陷/类型/严重度/依据/处置建议）
- 安全约束：仅放行 image/* 附件、路径规范化防穿越、照片数硬上限 4、全量审计
- 前端：工单详情 AI 卡片新增「📷 AI 看图识别」（有现场照片时出现）

### 2.2 维修知识库 RAG

- 新表 `ai_kb_document`（09-ai-deepen.sql，幂等）：标题+正文+行内 JSON 向量
- `POST /api/ai/kb/documents`（ADMIN，即时向量化）、`GET /api/ai/kb/search?q=`
- **诊断自动增强**：DiagnosisService 可选注入 KB（ObjectProvider），召回 TOP3
  摘录并入诊断上下文；知识检索失败 fail-open 不阻塞诊断
- 检索实现：查询向量化 → 全量启用文档内存余弦（`AiVectors`，带单测）→ TOP-K；
  百级文档规模无需向量引擎，接口不变可平滑替换
- 启用条件：`EQUIPCARE_AI_EMBEDDING_MODEL` 配置 + `EQUIPCARE_AI_KB_ENABLED=true`

## 3. 通知外发（notification/outbound/）

- 双通道互相独立、默认关闭：
  - **企业微信群机器人**：`EQUIPCARE_NOTIFY_WECOM_WEBHOOK_URL` 配置即启用；
    markdown 群播，10s 超时
  - **SMTP 邮件**：`EQUIPCARE_NOTIFY_MAIL_*`；按事件 receiverIds 查用户 email
    逐个发送（未填邮箱跳过）；自建 JavaMailSender（465 SSL / 其他 STARTTLS）
- 事件来源（与站内消息桥接并行的第二消费者）：
  SLA 超时预警 / 库存不足 / 巡检发现异常（工单状态流转不外发，防刷屏）
- 异常策略与桥接器一致：全部吞异常记日志——外发是尽力而为，
  抛错会让 outbox 重投、站内消息重复

## 4. 预测性维护（analytics）

- `GET /api/analytics/predictive`（health:view）：全量设备预测视图，按 7 天预测分升序
- 口径（只读既有表，零新表）：
  - **MTTR**：90 天完成单「开始维修→实际完成」均值（缺开始时间回退报修时间）
  - **MTBF**：90 天观察窗 ÷ 非取消工单数（零故障返回 null 而非无限大）
  - **趋势外推**：最近 ≤8 个健康快照最小二乘回归 → 斜率 → 预测分 = 最新分 + 斜率×7
- 风险分级：预测分 <60 → HIGH；斜率 <-0.5 分/天 → WATCH；快照不足 → WATCH（积累中）；其余 LOW
- 前端：旧前端新增「预测性维护」页（`/analytics/predictive`，health:view）：
  指标卡 + 设备预测表（纯 CSS 迷你趋势条 + 下滑红箭头 + 健康详情跳转）
