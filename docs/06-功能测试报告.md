| `stock-in.test.js` | 6 | 库存操作：未选备件/数量非法拦截、合法入库载荷、无权限空态 |

**测试发现并修复的真实缺陷 1 处**：`api.js` 原逻辑在「401 且无 refreshToken」时既不清凭据也不跳登录页（只有续期失败才清），用户会拿着过期令牌反复失败。已修复为：401 一律尝试续期，无刷新令牌或续期失败均清凭据回登录页（修复后 60/60 通过）。

## 七、遗留事项（如实列出）

1. **`application.yml` 保留了开发默认值**（如 DB 密码默认 `123456`、JWT 开发密钥）：均为环境变量可覆盖的 dev 便利默认，生产部署经 `docker-compose.yml` 强制注入强密码（`:?` 语法缺失即拒绝启动）。建议后续增加 `application-prod.yml` 将弱默认归零（第九阶段未做，避免动既有 dev 流程）。
2. **Docker 镜像构建与整栈启动未在本机执行**：开发机 Docker Desktop 未运行且沙箱策略禁止代为启动 GUI 程序。交付的 `Dockerfile.backend` / `Dockerfile.frontend` / `docker-compose.yml` / `nginx.conf` 已做语法与结构校验（compose 结构检查、init/backup 脚本 `bash -n` 通过），**容器级验证将在目标服务器按 `docs/07-部署操作文档.md` 首次部署时进行**。
3. 3 个已实现但未挂前端的接口（见二-4），保留为文档化运维接口。
