# 巡维云 EquipCare · AI 平台调用说明

> 第九阶段交付物。本说明如实描述项目开发中 AI 平台的使用方式、模型与调用形态，供评审复现参考。

---

## 一、使用的 AI 平台与模型

| 项 | 内容 |
|---|---|
| AI 平台 | WorkBuddy（Agent 模式，桌面端） |
| 主力模型 | GLM-5.3-Flash（智谱），全九个阶段统一使用 |
| 调用形态 | 会话式 Agent：自然语言下达阶段目标 → AI 规划任务清单 → 自主调用工具（读写文件、执行命令、访问数据库、浏览器验证）→ 汇报结果 → 人工验收 |
| 会话记录 | 全部人机对话与工具调用轨迹保存在本地会话文件（见 `ai-development-record.md` 附录 B），可逐条审计 |

## 二、调用方式（人机协同流程）

1. **阶段驱动**：人工按九个阶段下发目标提示词（原文见 `docs/09-AI提示词汇总.md`），每个提示词包含编号化的功能清单与硬性约束。
2. **AI 自主执行**：AI 在受控工作区内读写项目文件、执行 `mvn` / `python` / `mysql` 等命令、运行测试并解析输出、用 Playwright 驱动真实浏览器截图验证。
3. **真实反馈闭环**：AI 依据编译/测试/接口返回的真实报错自行定位与修复（九个阶段累计 95+ 项，见 `docs/ai-development-record.md` 附录 A），不做无依据的「声称完成」。
4. **人工把控边界**：人工只负责需求定义、约束设定、方案否决与验收确认；关键取舍（如前端技术栈偏差）由 AI 主动披露、留待人工裁决。
5. **真实性纪律**：AI 生成代码在所有文档中如实标注为 AI 生成；未执行的验证（如本机容器构建）如实列为未做项，不编造结果。

## 三、AI 在本项目中的具体产出

| 类别 | 产出 |
|---|---|
| 后端代码 | 330+ 个 Java 文件（含 10 个测试类、171 个测试用例），Spring Boot 3 / MyBatis Plus / JWT / POI / ZXing 技术栈 |
| 前端代码 | 44 个原生 ES Module 文件（零依赖、无构建），含深空工业主题 CSS 设计令牌体系 |
| 数据库 | 33 张表 schema、触发器、存储过程、演示数据与 7 个增量迁移脚本 |
| 测试 | 单元/集成测试、6 套冒烟脚本、UI 验证脚本（Playwright）、接口符合性脚本、Vitest 前端套件 |
| 文档 | 架构设计、数据库设计、接口说明、部署文档、演示说明、开发过程记录等 14+ 份 |
| 运维 | Docker 化交付物（Dockerfile × 2、compose、nginx.conf、初始化与备份脚本） |

## 四、可复现性说明

- 会话 jsonl 中保存了每一次工具调用的完整输入输出（命令、返回值、报错与修复），评审可按时间线还原任一阶段的开发过程。
- 各阶段测试命令与预期输出记录在 `docs/06-功能测试报告.md` 附录与 `docs/ai-development-record.md` 各阶段「八、测试结果」，均可在同版本代码上复现。
- 需要复核 AI 生成占比与人机分工时，见 `docs/ai-development-record.md` 附录 A「人机分工与责任边界」。

## 五、使用中的限制与人工介入点（如实说明）

1. **AI 无法自行启动 Docker Desktop**（沙箱安全策略），容器级验证留待目标服务器，已在测试报告中如实标注。
2. **AI 的记忆会被会话压缩**：跨阶段的关键决策（状态机规则、SQL 约束、踩坑记录）由 AI 主动写入工作区记忆文件持久化，避免凭记忆写出失真细节。
3. **服务器部署**：需求方明确「不要假设服务器 IP、账号、端口或密码」，故服务器部署步骤已备好方案与检查清单，待实际环境信息到位后执行——这是当前唯一未完成项，不是 AI 能力或项目完成度问题。
