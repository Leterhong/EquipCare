## 1. 渗透测试结论（黑盒实测）

### ✅ 防住的攻击（逐项实测证据）

| # | 攻击向量 | 结果 | 依据 |
|---|---|---|---|
| 1 | 未授权访问（7 个敏感端点无凭据探测） | 全部 401 | 白名单最小化：仅登录/刷新/健康/静态/错误 |
| 2 | JWT 伪造（dev 默认密钥签名完整结构 token） | 拒绝（1004 令牌无效） | 会话绑定：jti 必须在 TokenStore 有登记会话，签名合法≠有效 |
| 3 | SQL 注入（keyword/status `' OR '1'='1`、`DROP TABLE`、`%` 通配对比） | 无效 | MyBatis 全参数化；注入探针 total=0 与正常查询一致，`%` 通配 total=430 属 LIKE 正常语义；全部 mapper 无 `${}` 拼接 |
| 4 | SVG 存储型 XSS（含 onload 脚本的 svg + 白名单 bizType） | 上传被拒 | 扩展名白名单不含 svg（jpg/jpeg/png/gif/webp/pdf/doc/docx/xls/xlsx/mp4） |
| 5 | Content-Type 伪造 XSS（html 内容伪装 .jpg + text/html） | 不渲染 | 下载接口强制 `Content-Disposition: attachment`，浏览器不内联执行 |
| 6 | 点击劫持 / MIME 嗅探 | 有防护 | 响应头 `X-Frame-Options: DENY` + `X-Content-Type-Options: nosniff` |
| 7 | 路径穿越读任意文件 | 有防护 | 上传/下载均 `normalize()` + `startsWith(root)` 校验 |
| 8 | 路由探测 | 信息隐藏 | 无权限/不存在端点统一 404 语义（"接口不存在"），不暴露真实路由清单 |

### 🔴 发现并已修复（同日整改，回归实测通过）

**P1 · 登录暴力破解防护在 Redis 故障时完全失效**
- 渗透实测：无 Redis 环境连续 6 次错误密码，计数恒为「还可尝试 5 次」——fail-open 导致线上锁定策略归零
- 根因：`TokenStore.increaseLoginFailSafe` 降级路径直接返回 0
- 修复：三个 *Safe 方法降级时改用**进程内内存计数兜底**（窗口 TTL 语义与 Redis 版一致）；多实例部署各实例独立计数（防护减弱不失效）
- 回归：修复后连续错误 → 4→3→2→1→锁定→拒绝，**锁定生效**；降级单元测试断言同步更新

**P2 · CORS 任意来源 + 携带凭据组合**
- 配置为 `allowedOriginPatterns("*") + allowCredentials(true)`（经典反模式）
- 修复：`allowCredentials(false)`（认证走 Bearer 头，无 Cookie 依赖）+ 来源配置化
  `equipcare.cors.allowed-origins`（默认 `*`，生产收敛为前端域名）；实测预检响应不再携带 credentials 头

## 2. 静态审计结论

- **SQL 注入面**：全部 mapper 为参数化（`#{}`），无 `${}` 字符串拼接（命中的 `${}` 均为 Spring 属性占位符）
- **Actuator**：仅暴露 health/info，env/beans 等敏感端点关闭
- **Swagger**：prod 默认关闭（`equipcare.apidocs.enabled` 门控）
- **敏感信息**：`.env`/上传文件/日志不入库；seed.sql 无任何账号密码；文档已脱敏本机路径
